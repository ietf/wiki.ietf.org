Implementations of draft-ietf-bess-ebgp-dmz

Last verified: 2026-09-07

Scope

This report covers implementations that cumulatively regenerate the BGP Link Bandwidth Extended Community when advertising a route with a changed next hop.

The relevant layer is the Link Bandwidth Extended Community carried in the BGP Extended Communities path attribute. The cumulative calculation is performed by the advertising BGP speaker before the route is placed in Adj-RIB-Out. The receiver continues to interpret the resulting scalar as bandwidth available through the advertised next hop.

Independently implemented BGP stacks

FRR-derived product implementations

These products expose or deploy the FRR implementation. They are useful deployment evidence but should not be counted as separate protocol-code implementations unless the vendor identifies independent cumulative-processing code.

Partial or related implementations

Interpretation note

Public documentation establishes several interoperable implementations of cumulative SUM processing and, in some products, a cap on the resulting aggregate. Except where stated above, it does not establish implementation of the optional per-path calculation:

contributing-bandwidth_i = MIN(local-link-bandwidth_i, received-bandwidth_i)

followed by:

advertised-bandwidth = SUM(contributing-bandwidth_i)

Accordingly, the table distinguishes documented cumulative aggregation from complete implementation of every processing option described by draft-ietf-bess-ebgp-dmz.
