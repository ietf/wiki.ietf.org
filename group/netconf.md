# Netconf Implementations 

-   [YumaPro](http://www.yumaworks.com) is a YANG-based Unified Modular Automation Toolkit for NETCONF, HTTP/REST, and CLI. It includes a NETCONF-over-SSH client and server, YANG compiler, and other development tools.

-   Netconf4Android (Library) is an API that implements the Netconf protocol (RFC 4741) for building client applications (http://code.google.com/p/netconf4android/).

    -   Uses SSH-2 as the transport protocol (ganymed-ssh2);

    -   Compatible with Android API level 8 and above;

    -   Compatible with Java 1.5 and above.

-   [NuDesign](http://www.ndt-inc.com) provides a Windows based, [NetConf Agent](http://www.ndt-inc.com/Secure/RegToolYang.html?Product=YangDemoAgent) for the developers community to try out. The download includes a simple NetConf client, SSH client & server components, SSH NetConf subsystem and the core Demo Agent with NetConf, SNMPv3 and CLI access.

-   [ncclient](http://cnds.eecs.jacobs-university.de/software/ncclient) provides a Python API for client-side scripting and application development. Currently implements SSH transport, all RFC 4741 operations and capabilities as well as supports RFC 6241.

-   [libnetconf2](https://github.com/CESNET/libnetconf2) is a NETCONF library in C intended for building NETCONF clients and servers. It provides functions to connect NETCONF client and server to each other via SSH/TLS and including support for Call Home as well as to send/ receive NETCONF messages (Contact: Radek Krejci, CESNET https://github.com/CESNET/libnetconf2).

-   [Netopeer2](https://github.com/CESNET/Netopeer2) is a remote configuration system, which implements generic NETCONF server and client, both based on [libnetconf2](https://github.com/CESNET/libnetconf2). The client side includes a command-line interface so that simple requests can be generated manually, which is useful for debugging (Contact: Radek Krejci, CESNET https://github.com/CESNET/Netopeer2)

-   YencaP, a Netconf agent for Linux implemented in Python, distributed under LGPL as part of the [EnSuite (Extended Netconf Suite)](http://ensuite.sf.net/) collection [(download).](http://ensuite.sourceforge.net/download.html)

-   [YENCA](http://sourceforge.net/projects/yenca/), a Netconf agent for Linux implemented in C, available under GPL on SourceForge.

-   [Tail-f Systems](http://www.tail-f.com/) has a [NETCONF server](http://www.tail-f.com/on-device-configuration-management/) as well as command line and web interfaces, SNMP agent, REST interface and integrated configuration store. Tail-f also maintains an open source implementation of a [NETCONF client library](https://github.com/tail-f-systems/JNC) that can be integrated with network automation software.

-   [GoAhead embeddedMIND™](http://goahead.com/products/embeddedmind/default.aspx) is an extensible Netconf agent with integrated configuration store and CLI, SNMP and Web interfaces.

-   [XML Based Device Management](http://www.wipro.com/webpages/prodesign/reusableframeworks/ip/xml.htm) by Wipro, including an agent written in C and a manager in Java

-   An implementation written in C from [NEC Europe Ltd](http://www.netlab.nec.de/Projects/GMM.htm) in Germany

-   Another implementation written in C by http://www.postech.ac.kr/Postech in Korea

-   [XMS (eXtensible Management System)](http://www.6wind.com/Network.html), written in C, by 6WIND

-   Applied Informatics\' C++-based [NetConf implementation](http://www.appinf.com/en/products/netconf.html) based on the POCO framework.

-   [Netconf4j](http://code.google.com/p/netconf4j/). Standalone Java netconf implementation used in http://www.opennaas.org.

-   [NETCONF Browser](http://www.mg-soft.com/mgNetConfBrowser.html), a user friendly NETCONF GUI client/manager from MG-SOFT, based on MG-SOFT\'s own NETCONF V1 and V1.1 protocols. Application is implemented in Java.

-   [Visual YANG Designer](http://www.mg-soft.com/mgYangDesigner.html), a user friendly YANG file designer (creator, editor, modeler, builder) from MG-SOFT, based on MG-SOFT\'s own YANG compiler. Application is implemented in Java.

-   [NetconfX](http://www.centeredlogic.com/netconfx_main.html), an open-source Java NETCONF client implementation provided by [CenteredLogic](http://www.centeredlogic.com/) as part of its Element/Network Management platform.

## 1. Gegenstand dieser Review

Diese Review befasst sich mit RFC 2026 aus dem Jahr 1996 und seiner Bedeutung für die Entwicklung, Prüfung, Dokumentation und Weiterentwicklung von Internetstandards.

RFC 2026 trägt den Titel *The Internet Standards Process — Revision 3*. Das von Scott O. Bradner an der Harvard University verfasste Dokument beschreibt den Standardisierungsprozess für Protokolle und Verfahren innerhalb der Internetgemeinschaft.

Die vorliegende Dokumentation greift diesen Standardisierungsrahmen auf und ergänzt ihn um meine technische Untersuchung digitaler Textverarbeitung, Zeichenkodierung, automatisierter Informationsverarbeitung und Crawling.

Ziel ist es, die Zusammenhänge zwischen technischen Standards, maschineller Verarbeitung und automatisierter Erfassung digitaler Inhalte nachvollziehbar zu dokumentieren.

## 2. Internetstandards und automatisierte Informationsverarbeitung

Das Internet basiert auf dem Zusammenspiel miteinander verbundener Systeme, die über definierte Protokolle, Formate und Verfahren kommunizieren.

Im Mittelpunkt dieser Review stehen insbesondere:

- die Verarbeitung digitaler Texte und Zeichenfolgen;
- die technische Repräsentation von Buchstaben, Ziffern und Symbolen;
- die Interpretation strukturierter Eingaben durch Software;
- die automatisierte Erfassung und Indexierung digitaler Inhalte;
- die Verarbeitung von Suchanfragen und die Bereitstellung von Suchergebnissen;
- die Weiterentwicklung bestehender Protokolle durch Ergänzungen, Korrekturen und neue Spezifikationen.

Die Eingabe eines Suchbegriffs über eine Suchmaske und die anschließende Anzeige von Ergebnissen beruhen auf mehreren technischen Komponenten. Dazu gehören je nach System Crawling, Indexierung, Datenhaltung, Suchalgorithmen und die Verarbeitung von Nutzeranfragen.

Crawling ist ein wichtiger Bestandteil vieler Suchsysteme. Es ist jedoch von den übrigen Komponenten der Internetkommunikation und Informationsverarbeitung zu unterscheiden.

Diese Review untersucht die genannten Prozesse als zusammenhängendes technisches Themenfeld.

## 3. Historischer Untersuchungszusammenhang: 1996, Computersysteme und Automatisierung

Ein Bestandteil meiner Untersuchung ist die zeitliche Einordnung des Jahres 1996. Dabei untersuche ich mögliche Zusammenhänge zwischen damaligen Ereignissen im Bereich der Computersysteme, der Entwicklung automatisierter Prozesse und der Standardisierung des Internets.

In diesem Zusammenhang beziehe ich meine Recherche zu industriellen Systemen, Siemens-Bezügen, Diskettenlaufwerken und möglichen Übertragungswegen von Schadsoftware beziehungsweise automatisierten Abläufen ein.

Die Untersuchung befasst sich mit der Frage, welche technischen Mechanismen bei der Übertragung, Ausführung und Weiterverarbeitung digitaler Informationen eine Rolle spielen können und wie sich diese Mechanismen im Kontext späterer internetbasierter Automatisierung einordnen lassen.

Die Verbindung zwischen diesen historischen Untersuchungsgegenständen und RFC 2026 ist Bestandteil meines Forschungsansatzes. Die konkrete historische oder technische Kausalität ist anhand eigenständiger Quellen, Protokolle, Datensätze und nachvollziehbarer Belege zu untersuchen.

RFC 2026 dient hierbei als Referenz für den Internetstandardisierungsprozess des Jahres 1996.

## 4. Unicode, UTF-8 und digitale Textverarbeitung

Ein zentraler Bestandteil dieser Review ist die technische Verarbeitung von Texten, Buchstaben, Ziffern, Satzzeichen und Symbolen.

Dabei sind mehrere Ebenen zu unterscheiden:

- **Unicode:** definiert einen standardisierten Zeichenvorrat und ordnet Zeichen Codepoints zu.
- **UTF-8:** kodiert Unicode-Codepoints als Bytefolgen.
- **Textformate und Protokolle:** legen fest, wie Zeichenfolgen strukturiert und interpretiert werden.
- **Software und Suchsysteme:** verarbeiten digitale Inhalte entsprechend den implementierten Regeln.

Diese Ebenen bilden eine wesentliche Grundlage für die interoperable Verarbeitung mehrsprachiger und symbolhaltiger Inhalte.

Ein Ziel meiner Untersuchung ist es, die technische Behandlung von Zeichen und Texten so zu dokumentieren, dass auch Sonderzeichen, Satzzeichen, unterschiedliche Schriftsysteme, Wortbestandteile und Kodierungsvarianten berücksichtigt werden.

Dazu gehören insbesondere die Untersuchung von:

- Zeichenkodierungen und fehlerhaften Bytefolgen;
- Unicode-Codepoints und UTF-8-Sequenzen;
- Textnormalisierung;
- Parserregeln und Syntaxdefinitionen;
- Sonderzeichen und Satzzeichen;
- der Behandlung unerwarteter oder ungültiger Eingaben;
- der konsistenten Verarbeitung digitaler Textinhalte.

Die Untersuchung soll nachvollziehbar machen, welche Regeln für die technische Repräsentation und Verarbeitung von Zeichen gelten und wo unterschiedliche Systeme zusätzliche Interpretations- oder Verarbeitungsregeln anwenden.

Unicode und UTF-8 definieren dabei nicht automatisch die Bedeutung sämtlicher Wörter. Sie stellen die technische Grundlage für die Repräsentation von Zeichen bereit; die semantische Bedeutung von Wörtern wird durch weitere sprachliche, fachliche und softwareseitige Zusammenhänge bestimmt.
